Основной путь уже реализован: запрос мастера → чтение сайтов → нормализация модели/качества/наличия → независимые результаты каждого поставщика. Кеш пять минут; показано время получения данных. Продолжение выдачи загружается явно кнопкой. Недоступный источник не мешает остальным.

У GreenSpark подтверждена анонимная JS-cookie проверка. Воспроизводится фиксированный алгоритм страницы, без запуска стороннего JavaScript и без доступа к пользовательским cookies браузера. Защищённые кабинеты, CAPTCHA и ограничения доступа не обходятся.

Местный магазин подтверждён через выбор города на официальном сайте GreenSpark: `/?set_city=249529`, Комсомольск-на-Амуре, проспект Ленина, 4. Параметр выбора города работает и на странице поиска. В `__NUXT_DATA__` проверяется `$scurrentShop.id=249529` и `cityName`. Поля `quantity` и `prices` меняются вместе с магазином: наличие Москвы нельзя переносить на Комсомольск. Пустой `availableStores` означает отсутствие, а не неизвестный город; адрес берётся из подтверждённого текущего магазина.

## Другие варианты

1. **Публичные JSON-ответы и встроенные данные.** Предпочтительны, когда содержат те же данные, что интерфейс. У GreenSpark встроенный JSON уже используется. Публичная база `/local/api` обнаружена, но отдельный подтверждённый универсальный каталог API не заявляется.
2. **Страницы товаров.** Дополняют выдачу недостающим артикулом и характеристиками. Приложение ограничивает дополнительные проверки GreenSpark тремя кандидатами на точный артикул, чтобы не превращать поиск в массовый обход.
3. **Sitemap и каталоги.** Подходят для обнаружения ссылок и периодической индексации, но не гарантируют актуальную цену и наличие. У DVSOTA robots содержал ссылку на чужой sitemap — она не используется. Массовый обход поисковых URL не нужен.
4. **Анонимный браузер.** Резерв, если поставщик перенесёт данные в клиентский JavaScript. Требует отдельного процесса и больше ресурсов, чем текущий PHP-хостинг. Сейчас для четырёх источников не требуется.
5. **XLS/CSV/XML-прайсы и официальный API.** Могут дать более полный каталог и договорные цены. Это дополнительный вариант после появления кабинетов или договорённости; для текущего рабочего поиска не обязателен.
6. **Авторизованный кабинет.** Нужен только для персональных условий мастера. Его наличие у «Сервиса 101» пока не подтверждено. Текущие цены — анонимные цены сайтов, скидочные тарифы показаны отдельно с оговоркой об их применимости.

Полную подтверждённую доставку до Комсомольска-на-Амуре нельзя получить из полей, которых поставщики не публикуют. Для этого понадобится источник тарифов и сроков перевозчика либо данные поставщика по конкретному адресу/заказу. До появления этих данных стоимость и срок остаются неизвестными; они не заменяются догадкой.

## Сторонний сертификат сервис101.рф на текущем Beget

**Gordey_ap01. Проверено 16.11.2026.** Владелец разрешил сертификат основного домена и используемых поддоменов; сайты остаются на текущем Beget, отдельного VPS нет, в поддержку писать запрещено.

### Независимый выпуск выполнен

Сертификат получен **напрямую у Let's Encrypt**, через официальный Python-пакет `acme==5.10.0` из PyPI в отдельном локальном venv. Использован [DNS-01](https://letsencrypt.org/docs/challenge-types/#dns-01-challenge), без смены NS, A, MX и других существовавших записей. Четыре проверочные TXT были добавлены через DNS-форму Beget. После распространения записей центр сертификации подтвердил владение всеми именами. После выпуска четыре временные TXT удалены:

- `сервис101.рф` — `xn--101-eddot8cge.xn--p1ai`;
- `www.сервис101.рф`;
- `poisk.сервис101.рф`;
- `wp-stage.сервис101.рф`.

Издатель: `Let's Encrypt YR2`. Срок: **16.11.2026 06:58:50 UTC — 14.02.2027 06:58:49 UTC**. SHA-256 сертификата: `d2d1ffd199c32590e42d86394425e6bec718b5b8af8e155cee411eafdcccd068`. [Публичный сертификат центра сертификации](https://acme-v02.api.letsencrypt.org/acme/cert/064aebf09ce540ae4df8a7d12a8167ba27d6).

Локально проверены совпадение ключа, все четыре SAN, срок действия и цепочка доверия OpenSSL (`verify -purpose sslserver -verify_hostname ...`: OK). Ключ, CSR, цепочка и состояние ACME хранятся **вне checkout, Git и public_html**; доступ локальной папки ограничен владельцем, SYSTEM и администраторами. Приватный ключ никогда не загружался на сайт и не публиковался. Автоматическое продление и установка пока не настроены; ручной выпуск не обеспечивает их сам по себе.

### Независимый сертификат и действующий HTTPS

В [инструкции Beget](https://beget.com/ru/kb/manual/domeny-i-poddomeny#upravlenie-ssl-sertifikatami) описана вкладка «Установка SSL сертификата» с полями сертификата и приватного ключа. В реально доступной восстановленной панели аккаунта сейчас есть только «Каталог сертификатов», список поддоменов и заказ Let's Encrypt; формы импорта своего сертификата нет. Раздел настроек API тоже недоступен, проверенный адрес `https://api.beget.com/api/user/getAccountInfo` возвращает HTTP 301 на самого себя. Новый доступ API/SSH не включался. Независимый сертификат **выдан, но не установлен**, хранится как резервный комплект.

Пока выполнялся независимый выпуск, ранее отправленная заявка Beget **завершилась и HTTPS заработал**. Строгая проверка SSL с проверкой цепочки и имени (`ssl.create_default_context`, подключение к 45.130.41.161 с SNI каждого имени) прошла для основного домена, www, poisk и wp-stage. Установленный сертификат — другой: Let's Encrypt YR2, SHA-256 `c1c29778ebaa7304c5653faf53e3cce2da565d24842db99fb0cfbec6a059a3f0`, действует до **14.02.2027 07:01:50 UTC**, содержит шесть SAN, включая www.poisk и www.wp-stage. Независимый выпуск не следует выдавать за установку именно этого комплекта. Работающий сертификат из автоматической заявки не заменялся вручную.

Независимый комплект можно импортировать через `fullchain.pem` и `privkey.pem`, когда появится работоспособная форма импорта. Это ручной резерв: его продление и повторная установка отдельно не автоматизированы. По [инструкции Beget](https://beget.com/ru/kb/manual/domeny-i-poddomeny#vypusk-besplatnogo-ssl-sertifikata-lets-encrypt) продление сертификата, заказанного через панель, выполняется хостингом. Копирование PEM в папку сайта либо изменение PHP/.htaccess не подключает сертификат к HTTPS-серверу.

Контроль главной боевого сайта после выпуска: 34480 байт, SHA-256 `e2b128ac9a4c825daa1f7d44ac844483f76f7747e36d27cdcd4212a8f30173f6`, совпадает с исходной. После удаления временных TXT состав зоны сравнен с исходным: A основного домена, www, poisk и wp-stage прежние; MX/NS/другие TXT сохранены. Одновременно с установкой сертификата обнаружены смена старого A `www.poisk` с 91.106.207.93 на 45.130.41.161, нормализация TTL двух A до 600 и обновление серийного номера SOA. Это согласуется с [описанным Beget автоматическим изменением A при SSL](https://beget.com/ru/kb/how-to/sites/podklyuchenie-ssl-k-sajtu), отдельного ручного редактирования этих A в данном выпуске не выполнялось.

Подготовленный резервный архив HTTP-01 содержит только четыре публичных текстовых challenge-файла; он загружен вне public_html, **не распакован**, файлы действующих сайтов не менялись. Приватный ключ независимого сертификата на хостинг не загружался.

### Другие способы

[HTTP-01](https://letsencrypt.org/docs/challenge-types/#http-01-challenge) подтверждает домен файлом `.well-known/acme-challenge/` по порту 80; это альтернатива DNS-01 для выпуска, но не замена серверной установке сертификата. [DNS-01 с CNAME/NS-делегированием](https://letsencrypt.org/docs/challenge-types/#dns-01-challenge) только challenge-имён подходит для будущего автоматического продления без смены NS всей зоны, если найдётся работоспособный канал установки на хостинг.

Отдельный VPS с [Caddy Automatic HTTPS](https://caddyserver.com/docs/automatic-https) позволил бы управлять TLS самостоятельно, но VPS у владельца нет и он не приобретался. Внешний TLS-прокси/CDN требует отдельной настройки и защищённого соединения с сервером Beget; перенос DNS-зоны или трафика сайта на сторонний сервис не выполнялся. Самоподписанный сертификат не решает доверие обычных браузеров, а отключение проверки TLS не является установкой сертификата.

### Проверка опубликованного приложения

После установки TLS отдельное приложение poisk обновлено пакетом из проверенного Git-коммита, белый список публикации приведён к шести файлам. Включена ранее подготовленная переменная `POISK_DEPLOY_ENABLED`; [GitHub Actions](https://github.com/Gordey-ap01/10113/actions/runs/43828730348) успешно выполнил 51 проверку приложения, 15 проверок публикации и саму подписанную публикацию с подтверждением `/health`. Файлы основного сайта и WordPress staging в сборку не входят.

Проверка опубликованного сервиса: вход мастера по HTTPS с Secure-cookie, наличие таблицы и её настроек, живой запрос iPhone 12 / Экран ко всем четырём источникам. TAGGSM — 18 предложений, MOBA — 10, DVSOTA — 6, GreenSpark — 15; у GreenSpark семь позиций в местном наличии. Это один контрольный запрос, а не обещание полного каталога или неизменных цен.

Важное ограничение проверки с данного ПК: системный DNS возвращает `ERR_NAME_NOT_RESOLVED` для poisk, включая встроенный браузер. Google DNS публикует правильный A=45.130.41.161, а GitHub Actions обращается по имени успешно. Для локальной проверки опубликованного API адрес разрешён через Google DNS только внутри проверочного процесса; проверка цепочки и hostname TLS сохранена. Очистка кеша Windows не помогла; настройки DNS, hosts и туннеля не менялись. Полный вход в опубликованный интерфейс через встроенный браузер из-за этого не проверен; функциональность таблицы ранее проверена в реальном локальном браузере на той же версии кода.
