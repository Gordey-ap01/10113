# Получение данных поставщиков

Автор: **Gordey_ap01**. Проверено 16 ноября 2026 года реальными запросами без оптовых кабинетов.

| Источник | Рабочий способ | Подтверждённые поля | Ограничение |
| --- | --- | --- | --- |
| [TAGGSM](https://taggsm.ru/) | HTML выдачи `route=product/searcho`, затем карточки товаров | Название, ссылка, артикул, цены, наличие по городам | Поиск нечёткий: соседние модели отсекаются приложением. Проверяется Хабаровск. |
| [MOBA Хабаровск](https://khabarovsk.moba.ru/) | HTML `/catalog/?q=...&page=...` | Название, артикул, обычная и скидочная цена, наличие, поступление | В HTML есть скрытые шаблоны: они исключены. Поступление в магазин не считается доставкой клиенту. |
| [DVSOTA](https://parts.dvsota.ru/) | HTML `/catalog/?q=...` | Название, видимый артикул, цена, качественная оценка наличия | Внутренний schema SKU отличается от видимого артикула. Цена бывает не опубликована. Точное количество не сообщается. |
| [GreenSpark](https://green-spark.ru/) | Данные `__NUXT_DATA__` внутри HTML `/search/` с `set_city=249529`; для поиска по артикулу — проверка карточки | Название, ссылка, цены с названием тарифа, наличие в Комсомольске-на-Амуре, адрес магазина | Данные поиска не содержат артикул; он уточняется в карточке. ID и город текущего магазина проверяются; ответ другого региона отклоняется. |

Основной путь уже реализован: запрос мастера → чтение сайтов → нормализация модели/качества/наличия → независимые результаты каждого поставщика. Кеш пять минут; показано время получения данных. Продолжение выдачи загружается явно кнопкой. Недоступный источник не мешает остальным.

У GreenSpark подтверждена анонимная JS-cookie проверка. Воспроизводится фиксированный алгоритм страницы, без запуска стороннего JavaScript и без доступа к пользовательским cookies браузера. Защищённые кабинеты, CAPTCHA и ограничения доступа не обходятся.

Местный магазин подтверждён через выбор города на официальном сайте GreenSpark: `/?set_city=249529`, Комсомольск-на-Амуре, проспект Ленина, 4. Параметр выбора города работает и на странице поиска. В `__NUXT_DATA__` проверяется `$scurrentShop.id=249529` и `cityName`. Поля `quantity` и `prices` меняются вместе с магазином: наличие Москвы нельзя переносить на Комсомольск. Пустой `availableStores` означает отсутствие, а не неизвестный город; адрес берётся из подтверждённого текущего магазина.

## Другие варианты

1. **Публичные JSON-ответы и встроенные данные.** Предпочтительны, когда содержат те же данные, что интерфейс. У GreenSpark встроенный JSON уже используется. Публичная база `/local/api` обнаружена, но отдельный подтверждённый универсальный каталог API не заявляется.
2. **Страницы товаров.** Дополняют выдачу недостающим артикулом и характеристиками. Приложение ограничивает дополнительные проверки GreenSpark тремя кандидатами на точный артикул, чтобы не превращать поиск в массовый обход.
3. **Sitemap и каталоги.** Подходят для обнаружения ссылок и периодической индексации, но не гарантируют актуальную цену и наличие. У DVSOTA robots содержал ссылку на чужой sitemap — она не используется. Массовый обход поисковых URL не нужен.
4. **Анонимный браузер.** Резерв, если поставщик перенесёт данные в клиентский JavaScript. Требует отдельного процесса и больше ресурсов, чем текущий PHP-хостинг. Сейчас для четырёх источников не требуется.
5. **XLS/CSV/XML-прайсы и официальный API.** Могут дать более полный каталог и договорные цены. Это дополнительный вариант после появления кабинетов или договорённости; для текущего рабочего поиска не обязателен.
6. **Авторизованный кабинет.** Нужен только для персональных условий мастера. Его наличие у «Сервиса 101» пока не подтверждено. Текущие цены — анонимные цены сайтов, скидочные тарифы показаны отдельно с оговоркой об их применимости.

Полную подтверждённую доставку до Комсомольска-на-Амуре нельзя получить из полей, которых поставщики не публикуют. Для этого понадобится источник тарифов и сроков перевозчика либо данные поставщика по конкретному адресу/заказу. До появления этих данных стоимость и срок остаются неизвестными; они не заменяются догадкой.

Нельзя считать бинарник свободно распространяемой MIT-зависимостью по лицензии репозитория. Рекламные обещания прохождения любых проверок независимо не подтверждались.

## Отдельный сертификат poisk без заказа выпуска у Beget

Письмо на скриншоте сообщает об ошибке выпуска для **сервис101.рф**. `poisk` там не указан; причина ошибки не раскрыта. Это не доказательство невозможности отдельного выпуска для поддомена. После исследования владелец уточнил, что остаёмся на текущем Beget, и явно разрешил сертификат для основного сервис101.рф, а не только poisk. Рассмотренные ниже независимые варианты сохранены как техническая справка; текущий путь — сертификат основного домена с используемыми поддоменами. Другие настройки и данные действующих сайтов не входят в эту работу.

Выпуск и установка — разные операции. [Let's Encrypt DNS-01](https://letsencrypt.org/docs/challenge-types/#dns-01-challenge) позволяет выпустить сертификат только на `poisk.xn--101-eddot8cge.xn--p1ai`, подтвердив владение через TXT `_acme-challenge.poisk.xn--101-eddot8cge.xn--p1ai`. Сертификат не должен включать основной домен, wp-stage или wildcard. Для автоматического продления нужен работоспособный DNS API либо делегирование только этой challenge-записи через CNAME/NS. Смена NS всей зоны не требуется и не входит в разрешённую область.

Публичная read-only проверка Google DNS 16.11.2026: poisk A=45.130.41.161, AAAA нет; CAA у poisk и основного домена не опубликованы. Это не выявило CAA-запрета в проверенных записях, но ещё не является успешной ACME-проверкой. TXT challenge пока отсутствует. DNS не изменялся и сертификат в ходе исследования не заказывался.

1. **Сохранить сайт на Beget.** Можно независимо выпустить сертификат DNS-01, но затем Beget должен позволить привязать его ключ и цепочку именно к poisk, а также автоматизировать последующие установки. В текущей доступной панели подтверждена только общая форма основного домена с дополнительными поддоменами; способ отдельной загрузки своего сертификата не подтверждён. Сам файл сертификата эту серверную настройку не заменяет.
2. **Отдельный VPS только для poisk.** Направить только A-запись poisk на новый сервер, оставить остальные DNS/сайты на месте. [Caddy Automatic HTTPS](https://caddyserver.com/docs/automatic-https) получает и продлевает сертификат; PHP-приложение и потенциальный Python/Playwright-процесс размещаются отдельно. Нужны имеющийся сервер или согласованный новый тариф и доступ для развёртывания. Ничего не приобреталось и не переносилось.
3. **Отдельный TLS-прокси для poisk перед Beget.** Технически возможен на управляемом сервере, но соединение от прокси до Beget тоже должно быть защищено и проверяться. Вариант с передачей паролей по открытому HTTP не подходит. В данной ситуации перенос самого poisk на отдельный сервер проще, чем добавление второго слоя.

[HTTP-01](https://letsencrypt.org/docs/challenge-types/#http-01-challenge) — другой вариант подтверждения: статический файл в `poisk/public_html/.well-known/acme-challenge/`. `.htaccess` пропускает существующие файлы, но доступность конкретного challenge-файла извне перед выпуском ещё нужно проверить. Текущая автоматическая переадресация PHP для отсутствующих файлов не доказывает успешность HTTP-01. Данные/сертификаты двух существующих сайтов не участвуют ни в одном из предложенных вариантов.
