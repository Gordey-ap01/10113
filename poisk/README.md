# Поиск запчастей «Сервис 101»

Идея и продукт: **Gordey_ap01**.

Отдельное рабочее место мастера для Комсомольска-на-Амуре. Прямой поиск по публичным страницам TAGGSM, регионального MOBA, DVSOTA и GreenSpark. Оптовые кабинеты не обязательны. Это самостоятельное PHP-приложение; WordPress и основной сайт не используются.

- Единственная площадка: `/home/b/b9141846/poisk-service101`.

- `101service.ru` и `service101-wp-stage`, их PHP, БД, DNS и сертификаты не входят в публикацию.
- Workflow упаковывает ровно четыре PHP-модуля и два файла интерфейса. Корневой сайт репозитория не публикуется.
- Секреты, сессии, SQLite, журналы и cookies источников находятся **выше** `public_html` и исключены из Git.

## Данные и ограничения

Поиск выполняется по действию мастера, независимо по каждому источнику. Кеш — пять минут с сохранением фактического времени проверки. Если у поставщика есть продолжение выдачи, кнопка «Ещё предложения» загружает следующую страницу. Ограничение — 20 страниц на источник за один поиск; это защита от случайного массового обхода.

У TAGGSM и MOBA проверяется Хабаровск. DVSOTA сообщает наличие в каталоге; конкретный склад требует уточнения. GreenSpark возвращает данные выбранного сайтом магазина, часто Москвы: его название показано в карточке. Оптовые и скидочные цены показаны отдельно, их применимость нужно уточнять.

Отсутствующие цены, точные количества и доставка не выдумываются. Срок поступления в магазин не считается сроком доставки в Комсомольск-на-Амуре. Оригинальность, технология и состояние определяются только по словам в описании поставщика. Неуказанные признаки сохраняются как неизвестные. Аксессуары к экрану или аккумулятору не тарифицируются как замена основной детали.

Сервис сравнивает только цены деталей у поставщиков. Стоимость работы мастер определяет самостоятельно; ставки ремонта и итоговая стоимость ремонта не рассчитываются.

GreenSpark использует публичную проверку анонимного JS-cookie. Клиент воспроизводит только её фиксированное вычисление; произвольный код страниц не выполняется. Авторизация поставщиков, CAPTCHA, покупки и корзины не используются. Если поставщик меняет формат или ограничивает доступ, его ошибка показывается отдельно; старое наличие не выдаётся за обновлённое.

## Проверки

PHP 8.3+, расширения curl, DOM, mbstring, PDO SQLite, ZipArchive. Внешних PHP/JS-зависимостей нет.

```sh
php tests/run.php
php tests/deploy.php
node --check assets/app.js
php ops/probe.php 'iPhone 12' display
```

Fixtures — сокращённые реальные карточки поставщиков от 16.11.2026, используются для проверки парсеров. Интеграционный probe делает только чтение публичных страниц, запускается вручную. Он не включён в релиз.

## Публикация через GitHub

1. Проверить и отправить изменения в `feature/poisk-service101`.
2. Workflow `Poisk — isolated deployment` проверяет PHP 8.3, тесты и JavaScript; формирует архив с SHA-256 каждого разрешённого файла.
3. Если repository variable `POISK_DEPLOY_ENABLED=true`, workflow отправляет архив на фиксированный HTTPS-адрес. Секрет `POISK_DEPLOY_KEY` хранится только в GitHub Secrets и приватном config.php сервера.
4. Сервер проверяет HMAC, время, повтор запроса, размер, состав архива, отсутствие ссылок/переходов по каталогам, контрольные суммы и SHA коммита. Новая версия активируется атомарным переключением `current.json`.
5. Workflow проверяет `/health` и совпадение активного SHA.

Однократная установка: `ops/bootstrap.py` собирает обёртки, приватную конфигурацию и первый релиз **из указанного Git-коммита**. Архив загружается через защищённый файловый менеджер Beget только в новый `poisk-service101`, распаковывается там. Архив содержит секрет, поэтому его нельзя помещать в `public_html`, коммитить или прикладывать к issue/PR.

Первоначальный пароль мастера создаётся отдельно от пароля хостинга; на сервере хранится только хеш. В интерфейсе мастер может сменить пароль. Публичной регистрации нет.

Восстановление: повторно опубликовать проверенный предыдущий коммит через GitHub (новый push с revert). Старые каталоги релизов, БД и конфигурация сохраняются. При аварии допустимо переключить только `poisk-service101/current.json` на уже имеющийся проверенный SHA; это действие нужно записать в GitHub issue.

## HTTPS на Beget

Текущая форма Beget для поддоменов связана с сертификатом родительского домена. Заголовок «Сертификат для poisk» сам по себе не подтверждает изоляцию. **Не отправлять общую SSL-заявку и не менять сертификаты двух существующих сайтов.** До отдельного валидного сертификата вход в опубликованное приложение и автоматическая публикация не активируются. Проверку TLS не отключать.
