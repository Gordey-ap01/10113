# Каталог WordPress: проверка UX и исправления

Автор: **Gordey_ap01**. Проверено 25 октября 2026 года.

Изменения касаются плагина каталога на отдельной площадке Beget `service101-wp-stage`. Файлы темы, корень и база боевого сайта не входят в развёртывание.

| Обнаруженная проблема | Исправление |
|---|---|
| `includes/admin.php`, обработчик `action`: `wp_die` на любой ошибке терял ввод | JSON-ошибка остаётся в форме; без JS — возврат с краткоживущей копией, привязанной к пользователю |
| Не было проверки категории бренда до отправки | Всплывающее предупреждение, пояснение выбора нескольких категорий, отметка ошибки рядом с полем и возврат фокуса |
| Плоский список моделей скрывал структуру | Таблица категорий → таблица брендов → таблица моделей; дерево слева, хлебные крошки, поиск |
| Маленькое поле названия услуги, 12 видимых столбцов | Широкое название с переносом, основная таблица из 6 столбцов, дополнительные параметры раскрываются отдельно |
| Пользователь вручную задавал коды услуг | Стабильный UUID-код создаётся сервером; существующий код скрыт и проверяется на принадлежность модели |
| Отдельные кнопки удаления на каждой строке | Флажки выбора, общая кнопка внизу, текстовая пометка удаления, отмена, предварительный отчёт и отдельное применение |
| Пустые необязательные значения молча сохраняли старые данные | У редактора явное очищение полей; частичный Excel-импорт сохраняет прежний контракт |
| Нет защиты от частично переданной большой формы | Последний контрольный параметр формы; при обрезке запроса сервер отклоняет сохранение |
| HTML-поле WordPress `action` перекрывало свойство `form.action` при AJAX | Адрес запроса читается через `getAttribute('action')`; ошибка обнаружена в реальном браузерном тесте |

Применены [wp-plugin-development](https://github.com/WordPress/agent-skills/tree/trunk/skills/wp-plugin-development), [web-design-guidelines](https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines) и локальный навык frontend-ui-engineering. Нормы проверки: подписи полей, семантические ссылки и кнопки, видимый фокус, native dialog, сообщения `aria-live`, восстановление данных, защита от случайного ухода, явное подтверждение удаления.

Проверки на staging:

- Пропущенная категория и занятый адрес бренда: сообщение в окне, название и адрес сохранены.
- Без JavaScript: сервер возвращает тот же редактор со всеми введёнными значениями.
- Неверный nonce отклонён с HTTP 403; права администратора и ревизии продолжают проверяться.
- Переход из категории в бренд и модель; открытие услуг в окне.
- Выбор двух услуг, пометка, отмена; пустое название вызывает ошибку.
- Нулевая цена, автоматически созданный код, очищение необязательных значений, неизменность пропущенных строк.
- На отдельной одноразовой QA-модели три услуги: предварительный отчёт ничего не удаляет, применение удаляет только две выбранные, третья и услуги исходной модели сохраняются. QA-модель удалена; данные владельца совпадают с состоянием до теста.
- Проверка целостности: 118 моделей и 1 941 строка цен, ошибок связей нет. Функциональные сценарии покрыты `wordpress/tools/test-admin-ux.php`, `test-admin-delete-ui.php`, `test-admin-bulk-services.php`.
- Проверены 125 публичных маршрутов каталога, включая новую модель без услуг: явное пустое состояние, HTTPS, noindex тестовой площадки, вход WordPress и закрытые служебные файлы.
- Проверены обычный и узкий экран (390 px), доступность прокрутки таблицы с клавиатуры, подписи полей и консоль редактора без ошибок JavaScript.

Подтверждение в админке имеет два шага: «Проверить изменения перед сохранением» → «Применить проверенные изменения». Загрузка Excel по-прежнему не удаляет пропущенные строки. Смена глобального названия общего кода услуги по-прежнему показана в отчёте и описана в дополнительных настройках.
